# Backup & restore

With `ENABLE_BACKUPS=true`, `active/backup-config.sh` runs nightly at 03:30 and writes one AES-256-encrypted tarball of `CONFIG_DIR` to `BACKUP_DIR` — the databases, accounts, requests, indexers and profiles that cannot be regenerated. Media is deliberately not in it.

Related: [CONFIGURATION.md](CONFIGURATION.md#env) (`ENABLE_BACKUPS`, `BACKUP_DIR`, `BACKUP_KEEP`) · [AUTOMATION.md](AUTOMATION.md#the-schedule) · [UNINSTALL.md](UNINSTALL.md)

## What is in it

Everything under `CONFIG_DIR` — every app folder plus `controllarr/` (`users.json`, `settings.local`, `controllarr.env`) and the passphrase file itself — except `<app>/log`, `jellyfin/{transcodes,metadata,cache}` (re-fetched on the next scan) and `controllarr/cache` (posters). Paths are relative to the parent of `CONFIG_DIR` (`config/radarr/config.xml`).

**Not in it:** `DATA_DIR` (the media itself); the install directory's **`.env`, `secrets.env`, `tailscale.env`** — copy those by hand (600 for the last two), they are what reproduces your passwords, ports and keys; `warden.env`, the override, the Controllarr clone, `active/`, `INSTALL-SUMMARY.txt` (all regenerated by every install); Docker images. Tailscale's login state is under `CONFIG_DIR/tailscale`, so it *is* in it.

## Schedule, retention, failure

Cron `30 3 * * *` under `flock -n` + `timeout 1800`, log `active/backup-config.log`. Output `BACKUP_DIR/config-YYYYMMDD-HHMM.tar.gz.gpg`; the newest `BACKUP_KEEP` (7) are kept. tar exit 1 (*file changed as we read it* — live databases) is success; exit 2+ or a gpg failure logs `backup FAILED (tar=N gpg=N)` and removes the half-written file. Unreadable root-owned files are read through a throwaway `alpine` container. Needs `gpg` on the host.

The panel shows the newest archive's age (**Settings ▸ Backup & config**) and adds *No recent config backup* to Needs attention when backups are on and the newest file is older than 36 h.

## Encryption and the passphrase

`gpg --symmetric --cipher-algo AES256` with a random passphrase at **`CONFIG_DIR/.backup-passphrase`** (600, generated on the first run, deliberately outside `BACKUP_DIR` so the folder can be synced anywhere; `BACKUP_PASS_FILE` in `warden.env` moves it). **Keep a copy off the box** — the copy inside the tarball is encrypted with itself. A missing file is silently regenerated, so later backups would use a different key.

## Restore

```bash
cd ~/media-stack; CONFIG_DIR=/srv/media/config; BACKUP_DIR=/srv/media/backups; PASS=$CONFIG_DIR/.backup-passphrase
docker compose --env-file .env down                       # nothing may write while you overwrite
sudo mv "$CONFIG_DIR" "$CONFIG_DIR.old"                   # optional
gpg --batch --decrypt --passphrase-file "$PASS" "$BACKUP_DIR/config-YYYYMMDD-HHMM.tar.gz.gpg" | sudo tar xz -C "$(dirname "$CONFIG_DIR")"
docker compose --env-file .env up -d
```

Extract as the user that owns `CONFIG_DIR` (or fix with `chown -R PUID:PGID`). API keys are read live from the restored configs, so nothing needs re-wiring; Jellyfin re-downloads artwork on its first scan. **Fresh machine:** install the requirements, clone, put `.env` / `secrets.env` / `tailscale.env` back, `./install.sh` (accept every default), then the four lines above.

## Verify

```bash
cd ~/media-stack && WARDEN_ENV=$PWD/warden.env ./active/backup-config.sh          # prints the new file
gpg --batch -d --passphrase-file /srv/media/config/.backup-passphrase "$(ls -t /srv/media/backups/config-*.tar.gz.gpg | head -1)" | tar tz | head
```

*Bad session key* = the wrong passphrase file. Off-site: sync `BACKUP_DIR` anywhere (it is encrypted) plus, separately, the passphrase and the env files. The panel's **Save snapshot** (Settings ▸ Backup & config) holds app *settings* only — handy for undoing an experiment, not a backup.
